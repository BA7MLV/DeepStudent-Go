# 生成界面的设计准则

参考 Apple HIG 的清晰、层级、直接操作；不是照搬系统外观，更不是另造一套插件配置台。

- 一个主要任务，默认即用；标题描述用户内容，动作写“添加”“开始专注”等自然语言，不向用户展示 UUID、scope、revision。高级项按需展开；错误说明影响和下一步，技术细节仅在必要时展开。
- 使用宿主真实注入的 `--background`、`--foreground`、`--muted`、`--accent`、`--border`、`--radius`、`--danger`，而非其他运行时的 tokens。它们随主题更新；背景/正文有足够对比度，状态不只靠颜色。宿主已给按钮/输入框基础样式、focus-visible、.row/.stack/.muted/.error。
- body 使用系统字体，字号相对单位；沿用宿主圆角与语义色，不硬编码白底黑字，不加载远程字体/图标库。简单图标可用内联 SVG（装饰性 aria-hidden），不代替必要文字。
- 按窄侧栏与 360px 页面设计：内容流式排版、flex wrap、min-width:0；宽表格局部滚动，触控目标至少44px。文本输入字体不小于16px，标签关联控件。不要固定定位到宿主安全区，不加假抓手、不复制全站侧边栏。
- 标准 button/input/label、键盘可达、可见焦点；错误 role=alert，保存进度 role=status，避免频繁 aria-live 噪音。不强行抢焦点；长操作允许离开且由真实任务继续。
- 加载/空/成功/失败都是真实状态，不用示例成绩或动画冒充保存。输入中的草稿不被轮询覆盖；重复提交禁用，冲突重读并自然说明。
- 动效克制，遵守 prefers-reduced-motion。没有浏览器工具时不要声称看过布局、暗色、键盘或手机；交付时注明仅完成文件/配置核验。
