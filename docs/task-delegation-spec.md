# 任务级模型选择与子 Session 委派规范

状态：用户批准实施，2026-11-04。

本规范补充《Chat / Bot 任务级模型选择与子任务委派》六阶段计划。实施时两者同时满足；涉及子 Session 的最新语义以本规范为准。MUST 表示必需，SHOULD 表示默认应采用、偏离需记录原因。

## 1. 领域边界

- **Session** 保存可持续交流的上下文、默认模型、执行配置及来源关系。
- **Task** 保存目标、完成标准、冻结的模型选择、输入引用、依赖和最终交付。
- **Run** 表示一次具体执行尝试，记录状态、实际模型调用、工具操作和结果证据。
- MUST 明确三者映射到当前数据库与执行器的方式，每种状态只有一个权威写入源。允许复用既有表和执行适配器，不要求机械新增三套存储。
- MUST 将模型身份与权限分开；选模型不自动改变工具、工作区、技能或授权。

## 2. 委派类型

### 临时子任务（默认）

一次性检索、核对、分析、产出使用独立任务上下文。MUST 持久保存任务、执行和结果证据，但不得默认创建会话列表中的长期聊天。内部如需上下文容器，可以复用会话存储，显示和生命周期仍遵循临时任务语义。

### 新建持久子 Session

用户明确要求“新开一个会话”“以后交给它”“让我继续和它聊”等持续工作语义时，创建子 Session。MUST 保存来源 Session/Task、独立默认模型和执行配置。用户可以进入继续交流，主 Agent 可以在授权范围内继续向它派任务。

### 从历史分支

支持从确切消息边界建立分支。MUST 保存来源会话与消息身份，构造协议无关的必要历史快照；不得将供应商专用 continuation 标识用于另一个模型。分支后两边独立发展，后续父消息不得隐式同步进子会话。不得把任意摘要冒充完整历史。

### 向已有 Session 派任务

通过精确 Session ID 选择当前用户可访问的会话，复用其上下文与默认模型，也可单次覆盖模型。MUST 防止对同一会话并发追加互相穿插的模型回合；默认排队，明确的插入补充沿用现有队列语义。会话名有歧义时先解析/澄清。

### 临时任务转为持久会话

提供显式“转为独立会话”。MUST 复用已有任务结果及上下文证据，不重新执行已完成任务；转化操作幂等，不重复创建会话。

### 会话移交

Handoff 表示切换用户当前交流负责人，与上述委派不同。本轮不将 handoff 作为委派的隐式行为；主 Session 默认保留用户交互和汇总控制权。

## 3. 模型规范

- MUST 支持 Session 默认模型和 Task 单次覆盖；选择优先级为任务 > 会话 > 用途路由 > 账号默认。
- MUST 在命令受理时固定解析后的模型/候选和推理配置；后续设置改变、排队、重启、工具循环不改变该任务选择。
- MUST 在每次实际调用中传递该选择，而非只保存在 UI 或提示词中。
- 明确指定模型默认严格执行；不可用时报告原因。只有用户已允许的 fallback 才能改变实际模型，并记录实际调用链。
- MUST 用已配置目录将自然语言名称解析为供应商和模型引用；不捏造模型、凭据或访问权。
- “本次模型”不得修改全局设置；改变 Session 默认不影响已受理任务。运行期间改派创建关联的新尝试并保留旧证据。
- 输入区的执行模型与消息里的子任务模型可以不同，不应误报冲突；只有对同一任务的目标模型指令相互矛盾时才澄清。

## 4. 上下文与交付

- SHOULD 默认只传必要资料、完整相关约束、来源引用及完成标准，避免复制整个主对话。
- 分支历史为显式选项；独立子 Session 可以采用全新上下文或明确的资料包。
- MUST 保留当前执行范围内有效的系统/项目指令、权限边界；不能将子任务输出升级为系统指令或执行授权。
- 子任务默认向主任务交付结构化状态、结论、产物、验证证据、未完成事项和实际模型。主 Agent 再汇总，用户可以查看子结果。
- MUST 区分“已派发”和“已完成”；后台任务完成后通过持久交付事件通知原会话。父回合已结束时创建新的续接回合，不改写旧回答。
- 父任务的返回目的地与子 Session 当前活跃视图分离；用户进入子会话不应导致结果错投。
- 子任务的提问和审批 MUST 绑定精确 Task/Run/操作身份，原会话的回复不能误投给另一个任务。

## 5. 生命周期、并发与可靠性

- Task 结束不等于 Session 删除；关闭页面或切换模型不等于新建 Session。
- 默认第一版只开放一层委派，支持同层有限数量的子任务和依赖链，拒绝循环依赖及递归绕过。
- 父任务等待 MUST 持久化并释放运行槽；默认并发为 1 时父子流程也必须完成。
- 工作区锁交接 MUST 先结算当前操作；存在在途命令或不确定副作用时不得直接放锁。恢复时重新获取锁并检查版本。
- 对共享工作区的写操作遵守现有互斥；独立研究/独立输出可受控并行。
- 创建、提升会话和结果回传 MUST 幂等。依赖事件可重放，但不得重复执行任务或生成重复完成消息。
- 重启恢复已知安全的等待/交付；结果不确定的外部操作先核对，不盲目重放。
- 父任务取消级联它拥有的活动委派任务；发往已有 Session 时，仅取消本次委派创建的任务，不取消该会话其他任务或删除会话。
- 明确后台任务在父回合正常结束后继续；用户显式取消根任务时仍遵循级联规则。
- 根任务预算 MUST 汇总全部子任务使用量，不能通过开 Session 绕过限制；价格未知时如实显示未知。

## 6. 工具与客户端接口

实现模型发现、任务创建/读取/等待/取消，以及会话创建/分支/发送/读取等窄接口。可以按现有工具命名组织，不要求固定工具名称。MUST 使用结构化参数和服务端验证，并给模型提供用途、默认值、例子及返回状态说明。

统一 Chat、Bot、IM 的后端语义；沿用现有 typed Remote、ClientRuntime 和事件投影，禁止为各入口复制调度逻辑。跨账户、归档和授权规则在服务端执行。Chat 不因委派自动取得 Bot shell；显式使用已授权执行配置时沿用现有规则。

Chat/Bot 保留各自现有视觉风格，展示本次模型、必要任务状态和可访问的子会话入口。IM 通过短文本与任务标识完成选择、澄清和结果交付。纯本地模式明确能力边界，不把服务器故障自动转成本地执行。

## 7. 必须验收的用户流程

1. Chat 与 Bot 各发送一项模型 B 的任务：账号和会话默认 A 不变；工具多轮、排队和重启后仍调用 B。
2. 临时委派完成并回传：无多余长期会话，完整记录可查；取消和失败正确呈现。
3. 明确新建模型 B 的子 Session：能打开续聊，追加任务复用上下文，单次模型 C 覆盖后默认仍为 B。
4. 从指定历史消息分支并更换模型：必要上下文正确，父子后续消息独立，跨协议无错误 continuation。
5. 向已有且正在工作的 Session 派任务：顺序执行不串消息；取消此次委派不影响其他任务。
6. 临时任务转独立会话：重复点击、响应丢失和刷新均不重复执行/创建。
7. A 起草、B 核对、主 Agent 汇总：依赖顺序正确，子结果与实际模型可核对。
8. 并发为 1、共享工作区、父等待、取消、权限撤销、服务重启和迟到回传的组合无死锁、越权或重复副作用。
9. 关闭全部浏览器后服务端继续；重连/跨设备/IM 回传不重复通知；未知模型及明确模型不可用时不静默替换。
10. 假模型验证协议与调度；实际模型质量/费用评测单独标明证据和授权，不能将前者替代后者。

## 8. 实施要求

按原计划 P1–P6 落地，将本规范的 Session 契约纳入 P1，生命周期纳入 P2，自然语言入口纳入 P3，用户交互纳入 P4，依赖并发纳入 P5，全部场景纳入 P6。完成阶段后勾选原计划对应项；被外部条件阻塞的验收应明确记录，不虚报完成。

实施前检查当前代码与并发改动，复用最新任务底座。保护用户数据和其他工作；不以旧协议兼容为目标，也不因此清库。执行相关类型检查、生成契约检查、边界检查、构建和有意义的端到端故障测试。

参考：OpenAI Agents SDK 的 agents-as-tools、handoffs、sessions；Anthropic 的 routing、orchestrator-workers。采用成熟模式不等于需要引入对应 SDK。自动多 Agent 拆分是否默认启用，由任务质量、延迟和费用评测决定。
