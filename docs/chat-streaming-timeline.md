# Chat 追加式流式时间线

库聊天与课程问答共用服务端工具循环；不改变 Bot 执行器，也不引入额外的 `send_message` 工具。

## 不变量

- 已交付正文只追加。每轮协议消息与用户看到的累计正文分开维护；工具轮的说明不是可被最终回答替换的占位符。
- `ResponseSegment` 是「过程组 + 后续正文」的起点。正文与推理偏移采用 JavaScript UTF-16 单位，工具偏移采用累计 trace 下标。从正文返回推理或工具活动时追加锚点，不修改旧锚点。
- 锚点必须落在 Markdown 块边界：正文停在未闭合的 ``` / ~~~ 围栏内时，新锚点延后到围栏起始行；历史数据中落在围栏内的锚点在渲染时回退到围栏起点并合并不再前进的锚点，任何切片都不产生未闭合围栏。重复的 widget 引用连同首尾围栏标记一起等长留白，不残留孤立的反引号。
- progress、聊天行、最终结果与委派检查点保存同一份分段。刷新、历史重放和续写不推测历史工具位置；旧数据或无效锚点回退为完整过程与正文，不丢文本。
- 工具 trace 使用服务端任务/轮次/下标标识，不信任模型重复的调用 ID。作品引用在工具提交后固定在正文中；重复引用仅等长留白，不改变后续偏移和组件身份。
- 有工具调用则继续循环；正常纯文本回答立即结束。轮数受策略限制，空回答仅允许一次无工具收尾；空收尾或截断输出保留断点并标记中断，不伪装成功。截断的工具参数不执行。
- 流式 progress 最多约每 100 ms 写入；聊天行在边界或约每秒保存，避免每个 token 重写完整协议历史。进程崩溃可能损失最后一秒正文，不自动重放未知工具副作用。

## 验证

```sh
npm run test:chat:timeline
npm run test:chat:timeline:e2e
CHAT_TIMELINE_BROWSER=webkit npm run test:chat:timeline:e2e
```

服务端测试覆盖三种模型协议、工具/说明交错、同轮正文/推理交错、纯文本终止、空收尾、截断、取消、异常续写、课程问答及真实委派挂起/重启恢复。浏览器测试使用真实登录、API、SQLite 与模型 SSE，验证 DOM 顺序、作品 iframe 身份及交互状态、生成中刷新和历史重放。

虚拟消息列表在挂载提交后绑定滚动容器，避免历史数据与父容器同时挂载时，子布局效果先读到空 ref，导致视口一直为 0。刷新恢复不依赖后续 token 触发重渲染。
