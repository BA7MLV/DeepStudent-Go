认证状态与选定会话的原始记录仅写入本机权限受限临时目录，未加入仓库。以下只记聚合测量，不记录正文、图片、口令或 Token。

## 线上基线

真实部署、真实账号、无人工网络延迟，每个目标首次切换 n=3；不是本地夹具。A/B/C 为按选定目标顺序的匿名标签。

| 会话 | 可见耗时中位数 | 三轮范围 | 切换期间 WS 应用层字节 |
| --- | ---: | ---: | ---: |
| A | 11.52 s | 9.23–15.41 s | 5,117,344 |
| B | 9.37 s | 8.77–14.41 s | 5,095,425 |
| C | 7.35 s | 6.60–10.43 s | 4,178,775 |

通常同一会话元数据重复 HTTP 读取两次；缓存切回 A 约 94–149 ms。WS 数字包含同期后台订阅/记录同步，不等于单一会话载荷，也不是压缩后的网络流量。计时从实际点击到新消息出现且列表完成定位，受网络/服务器/渲染共同影响。

最初几次探针曾过早把侧栏唯一的活动占位行误当作导航加载完成，未命中目标；最终版本等待多条真实导航行后完成上述三轮。首次非稳定轮测得 29.6 s，不混入该表。测量不能用于证明所有账号或所有网络下的 P95。

## 已实现

1. `session-row.ts` 将 UI 消息投影与完整业务记录分开。会话首屏、旧页、journal 事件和 gap 修复均去掉顶层 `modelTrace`、`modelRequests`，在 SQLite 返回 Node 前就剔除；保留所有其他字段，包括附件、推理、工具、卡片和恢复信息。完整精确键与历史遍历仍返回原始记录，不修改存储。
2. journal 新基线只读取一次最新消息窗口。每次增量唤醒只读元数据/任务及对应事件；chunk 与 ready 之间仍独立检查会话归属和是否删除，不因优化取消权限检查。旧分页游标缺少 role 时仅查询该标量，不解析整条模型轨迹。
3. `loadSession` 在发布活动选择前建立每会话共享 Promise。点击、页面 effect 和重入调用共同等待元数据、journal ready 与草稿恢复，避免后到 token 使前次调用提前完成。加载中的会话暂不被空闲订阅清理，A→B→A 可复用同一次加载；完成/账号清理时释放。

## 同一批真实记录的隔离回放

线上只导出三条目标会话的元数据和六条消息（只读），在独立 SQLite/账号、真实 Chromium、Vite 源码环境分别回放优化前后各三轮。禁止外部网络/模型调用；先等背景基线结束，再测切换。这不是生产制品或线上优化后测量。

| 会话 | 优化前中位数 | 优化后中位数 | 会话 WS 应用层字节前 → 后 | 减少 |
| --- | ---: | ---: | ---: | ---: |
| A | 403.5 ms | 226.2 ms | 3,441,825 → 1,711,751 | 50.3% |
| B | 333.5 ms | 201.4 ms | 2,359,471 → 1,149,656 | 51.3% |
| C | 309.8 ms | 131.6 ms | 2,125,652 → 1,043,758 | 50.9% |

三会话首次元数据读取均由 2 → 1，最新消息窗口投影读取由 4 → 1；缓存切回窗口投影由 1 → 0。无页面异常，消息数与错误状态正常。独立 Vite 缓存预热和本机负载会影响计时，不把本地改善比例套用到线上 7–12 秒。
