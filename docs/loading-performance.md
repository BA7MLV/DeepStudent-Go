# 加载链路与按需文件读取

## 行为

- 基线与增量记录同步只保存 `$file` 引用，不下载、哈希或等待文件正文。
- 封面、讲义配图、聊天帧图使用浏览器原生 `loading="lazy"`；资料卡的 Markdown 文本封面仅在接近视口时读取和绘制。
- DOCX 预览、附件读取、导出和图片工具调用 `store/cloudBlob.ts` 按需取字节；历史本地 Blob 仍可读取，不改写用户草稿。
- 播放页动态取色同样按需解析一张帧图为 Blob URL，避免前后端跨域部署时 canvas 被远程图片污染。
- 同一账号/文件的同时读取合并为一个请求，下载并发最多 4。取消视图只取消该等待者；账号生命周期结束会取消整个旧账号的下载。
- 按需字节缓存在账号自己的 IndexedDB，LRU 限制 128 项和 32MiB；超过预算的单文件直接使用、不缓存。淘汰只删除可重建缓存，不删除草稿、上传原稿或命令日志。缓存配额错误不阻断已成功下载的内容。
- 原生图片使用 HTTP 私有缓存与 ETag；服务端先检查账号和文件归属，再返回 304，不使用绕过鉴权的长期公开缓存。
- 目录切回时先显示该账号运行时保留的目录，新的订阅同时重新验证；所有写命令仍由服务端授权并校验文件版本。编辑器文档仍要求 ready 快照。
- 偏好初始化与记录基线并行；本地偏好先恢复。后台启动的失败阶段使用带抖动的指数退避，并支持 online 立即唤醒；成功的偏好订阅不因记录重试而重建。
- records epoch 与 SQLite 一起持久化，普通 API 重启不会强迫全量重建。账号重置清除 epoch；未来游标仍触发重建。
- 记录按表批量写入，复用首次探测页；重建仍在 staging 中完成后一次发布，保留上一份完整视图及所有私有草稿。
- 目录/文档不再因无关学习文本、卡片、时长或普通偏好更新而重新扫描。聊天附件迁移相关的失效通知保留。

## 边界

这是文件正文/预览懒加载，不是将所有业务记录改造成按页面分页的协议。首次记录基线仍分页同步所有业务记录，并保持原子发布；后续通常增量同步。超大记录库如仍有性能问题，需要另做按领域投影与首屏分页设计，而不能直接打破现有跨表一致性。

本轮没有部署，也没有清理既有账号数据或调用付费模型。生产整页渲染耗时、实际服务器负载和 Safari 真机未据此推断。

## 验证

`npm run test:loading` 包含真实 API、Chromium、IndexedDB 和隔离 SQLite 夹具，以及文件缓存单测：

- 1000 条消息、8 个小 PNG；源模块预加载，计时不含 Vite 编译或整页渲染。
- 调查旧链路：无额外延迟约 268ms，每请求人工增加 150ms 时约 2924ms。
- 当前复验：约 197ms / 1229ms，基线文件 GET 为 0，记录请求 6 次（原来 7 次，另有 8 次串行文件 GET）。这些是隔离单次样本，不是生产承诺。
- 缓存重启只进行一次增量 recordsPage；首次按需并发读取同一文件仅一次 GET，之后持久缓存复用。
- 验证启动失败的定时与 online 自动恢复、文件 503 不影响已同步消息、中途重建失败不破坏上份视图、私有草稿保留、目录重连中复用缓存、图片实际解码、304 前鉴权。
- 单测覆盖并发上限、取消共享等待者、账号切换后的迟到响应拒绝、缓存写配额失败、项数/字节预算与大文件绕过缓存。

其他已通过：API/Web 构建、账号生命周期单测及真实浏览器回归、云事务回归、真实多标签 Web Locks/空闲 60 秒零 records 请求、讲义服务端持久化、大文件/Range 回归。
